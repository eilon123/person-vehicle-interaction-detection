Algorithm summary

  1. Detection. Every decoded frame is processed by C:/Users/eilon/hw work/person-vehicle-interaction/models/yolo26x.pt at image size 960 with detection confidence at least 0.2.
  2. Tracking. botsort.yaml assigns stable local person and vehicle IDs within a clip. IDs are reset for each clip.
  3. Candidate generation. The pipeline proposes person–vehicle windows from spatial proximity (near margin 0.2), track appearance/disappearance (gap 1.0 s), and temporal context of 1.5 s. When a person is near multiple vehicles in one frame, only the nearest normalized box gap is retained.
  4. Temporal verification. For each candidate, Qwen/Qwen2.5-VL-7B-Instruct (revision cc594898137f460bfe9f0759e9844b3ce807cfb5) examines 16 chronologically selected frames. It decides whether an interaction occurred, its action type, its person–vehicle pair, and supported evidence frames. Inference uses 4-bit loading: True.
  5. Event assembly. Overlapping duplicate proposals for the same supported action and pair are merged; disjoint supported spans remain separate. If context windows create simultaneous assignments of one person to different vehicles, the spans are trimmed using the closest available track geometry, with verifier evidence and stable IDs as fallbacks. The finalized event JSON is the source of truth for both metrics and video overlays.
  6. Evaluation. Thresholded event precision, recall, and F1 use temporal IoU ≥ 0.5. Participant IDs are ignored in the thresholded event metric; this evaluates temporal event presence. The separate Time overlap IoU has no threshold: it unions all predicted and reference interaction spans, so simultaneous actions do not double-count time.
